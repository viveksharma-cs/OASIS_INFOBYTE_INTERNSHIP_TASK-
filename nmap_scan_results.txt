5. OPEN PORT ANALYSIS
================================================================

PORT 22/tcp — SSH (OpenSSH 10.4p1, Debian)
--------------------------------------------
What it does:
  SSH (Secure Shell) provides encrypted remote command-line access
  to a machine. It's the standard way administrators log into
  Linux servers remotely, and also supports secure file transfer
  (SFTP/SCP) and port forwarding/tunneling.

Security risk assessment:
  - Baseline risk is LOW when properly configured: SSH traffic is
    encrypted, and the version detected (OpenSSH 10.4p1) is
    current, so it isn't exposed to old known CVEs tied to
    outdated OpenSSH releases.
  - Risk increases significantly if:
      * Password authentication is enabled instead of key-based
        auth (makes it vulnerable to brute-force/credential-
        stuffing attacks).
      * Root login is permitted directly (PermitRootLogin yes).
      * It is exposed to the public internet without a firewall,
        fail2ban, or rate-limiting.
  - Recommended hardening: disable password auth in favor of SSH
    keys, disable root login, and restrict access with a firewall
    (e.g. ufw) or by binding SSH to specific trusted IPs.

PORT 80/tcp — HTTP (Apache httpd 2.4.66)
--------------------------------------------
What it does:
  Apache HTTP Server serves web content over unencrypted HTTP.
  It's one of the most widely deployed web servers in the world,
  used to host websites, APIs, and web applications.

Security risk assessment:
  - Baseline risk is MODERATE: HTTP (unlike HTTPS) transmits data
    in plaintext, so any content served — including login forms
    or session cookies, if present — could be intercepted via a
    man-in-the-middle attack.
  - Version detection banners (like "Apache httpd 2.4.66") are
    themselves a minor risk: they tell an attacker exactly which
    version to look up known vulnerabilities for.
  - Common Apache risks include outdated modules, directory
    listing left enabled, default/example pages left in place,
    and misconfigured permissions.
  - Recommended hardening: serve over HTTPS (TLS) instead of plain
    HTTP, disable the Apache version banner in server config
    (ServerTokens Prod), disable directory listing (Options
    -Indexes), and keep Apache patched.
